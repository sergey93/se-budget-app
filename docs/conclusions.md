# Итоговые выводы

## Какие ошибки найдены и почему их не заметили сразу

Не были определены точное отклонение от бюджета и ограничения работы без сети.
Также не хватало тестов границы лимита и офлайн-ветви.
Эти места легко пропустить, когда документы проверяются по отдельности.
Сравнение требований со сценариями и тестами помогло увидеть пробелы.

## Какая практика оказалась самой полезной

Самой полезной считаю ревью по чек-листу. Оно помогает проверить связи
между требованиями, архитектурой и тестами. Общие фразы заменяются точными
условиями, по которым можно принять результат разработки. Git сохраняет историю
этих исправлений и их причины после создания коммитов.

## С чего начать реальную разработку

Сначала нужно проверить хранение и шифрование на прототипе и уточнить управление ключами.
Затем реализовать локальный учёт по плану спринта. До подключения групп
нужно проверить права доступа и повторную синхронизацию.
После этого можно расширять приложение, сохраняя работающий личный учёт.
